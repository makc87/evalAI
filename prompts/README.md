# Промпты и связь с результатами

Рабочий промпт для main_dotpoin_eval.py: prompts/current.txt.
Корневой prompt.txt оставлен как устаревшая копия для совместимости;
раннер его больше не читает. Редактируйте только prompts/current.txt.

После проверки всех кейсов, до создания клиента, раннер сохраняет в
prompts/versions/<полный SHA-256>.txt точный текст, передаваемый агенту.
Как и раньше, перед отправкой используется str.strip(). Хеш вычисляется
по UTF-8 этой строки. Существующий снимок проверяется, а не перезаписывается.
Неизменный текст использует тот же снимок.

Каждый запуск создаёт отдельный reports/<run_id>.json. run_id одновременно
служит именем сессии evaluate() на дашборде и включает короткий хеш промпта.
В отчёте: полный хеш, относительный путь к снимку от корня проекта, время UTC,
имена моделей агента и оценщика, статус и возвращённые результаты evaluate().
Два запуска одного промпта имеют разные run_id и отчёты.

Pydantic-объекты и dataclass сохраняются структурно. Для неизвестных типов
результатов используется явно помеченный repr (serialization: repr): это
текстовое представление, а не гарантированный набор полей метрик.
Совместимость с настоящим результатом eval_lib нужно проверить живым прогоном.

Невалидный набор не создаёт снимков/отчётов и не вызывает клиента.
Ошибка записи до генерации останавливает запросы. Ошибка генерации или оценки
по возможности отмечается status=failed; сохраняется только тип исключения.
Жёсткое завершение процесса может оставить status=running.
API-ключ и полный Settings в отчёт не записываются.

Архив и отчёты локальные и исключены из Git. Для передачи результатов
передавайте вместе reports/ и prompts/versions/, сохраняя структуру папок.
Отчёты могут содержать пользовательские данные из результатов оценки.
main.py (оценка сохранённого ответа) не изменён.

Офлайн-проверка: python -m pytest -q
Живой прогон: python main_dotpoin_eval.py
